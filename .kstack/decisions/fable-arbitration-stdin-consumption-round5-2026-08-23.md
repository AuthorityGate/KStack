# Fable arbitration ruling — expert-persona-library, round 5 directive

**Arbiter:** Fable, first invocation on this design. **Trigger accepted as genuine:** simultaneous confidence drop from both reviewers (Codex 66→61, Opus 76→70) with independent convergence on the same root defect — the round-4 stdin `finish` fix does not confirm consumption for sub-pipe-buffer payloads, and the 80 KiB fixture is structurally incapable of detecting that. This is the second consecutive round the same concern has resurfaced unresolved; arbitration is warranted.

## Ruling 1 — stdin consumption confirmation (SEC-STDIN-ACK / stdin-finish-below-pipe-buffer)

**Finding of fact, load-bearing:** parent-side proof that a non-cooperative child consumed a pipe payload is **impossible** for payloads under the OS pipe buffer. `finish` fires on kernel flush whether or not the child ever calls `read()`; no EPIPE occurs; no observable event distinguishes "read everything" from "read nothing, exited 0." No transport-side strengthening can close this gap. Round 5 must stop iterating on the transport signal.

**Codex's trusted-relay proposal is rejected:** a relay that fully receives stdin before invoking the provider merely relocates the identical pipe-consumption gap one hop downstream — the relay→provider pipe has the same semantics. Do not implement it.

**Round 5 shall implement both of the following:**

**(a) Settle-point hygiene — Opus's implementable rule, adopted verbatim.** A dispatch is delivered-to-OS only when stdin `finish` has fired AND child `close` is observed with exit 0. Acceptance is evaluated in the child `close` handler, with all handlers installed before the write; any stdin/write error (EPIPE or otherwise) delivered at any point before that evaluation is fatal (`KSTACK_STDIN_DELIVERY_FAILED`). This defines the currently-undefined error-observation window. It is necessary hygiene, and the design must label it as "delivery to the OS pipe" — not consumption.

**(b) Terminal nonce echo — the consumption mechanism.** The composer generates one random nonce per dispatch (format `KSTACK-ECHO-<16 lowercase hex>`, chosen so no sanitizer credential pattern can plausibly match it) and places its value as the **final line of the `KSTACK_OUTPUT_CONTRACT` body, immediately before the closing tag**, so only trusted constant bytes follow it. The output contract requires the provider's response to echo that nonce in a named field. The runner validates the echo against **raw stdout, pre-sanitization**, and records `echoVerified` in the manifest. A missing or wrong echo fails closed as `KSTACK_CONSUMPTION_UNCONFIRMED`: no manifest, no approval envelope.

**Why this closes the gap:** pipe reads are in-order with no gaps — a child cannot obtain the terminal bytes without having read the entire preceding stream. And the model's own output is the only signal that transits every intermediary (CLI, API, model), so it is the only place a consumption acknowledgment can live. Echoing the tail proves the complete byte stream was read out of the pipe and that its terminal token was available to whatever produced the output.

**Required consequential amendments (state these in the round-5 draft, or they will be flagged as contradictions):**

- The round-4 sentence "`KSTACK_DISPATCH_CONTRACT` and `KSTACK_OUTPUT_CONTRACT` … accept no free-text arguments and perform zero caller interpolation" must be amended: exactly one composer-generated random hex atom is permitted, in a fixed-grammar position, generated by trusted code, never caller-influenced. Extend the table-driven injection test to prove the nonce path cannot carry caller data. Lowercase hex trivially satisfies the angle/backslash delimiter invariant, so the compositional proof is unaffected — say so explicitly.
- The nonce makes `dispatchPromptSha256` unique per attempt even for identical design+persona+task. This is not a regression: dual review composes one shared buffer (one nonce, one digest for both children), and the variant registry already treats each attempt as a distinct record. State this preemptively.
- **`none` mode:** byte-preservation forbids injecting a nonce, so `none` keeps only mechanism (a). Add a manifest field `deliveryAssurance` distinguishing `"pipe-flush+exit"` (none) from `"pipe-flush+exit+terminal-echo"` (explicit). This is a disclosed residual, not an oversight — it is exactly today's baseline for existing callers.
- **Honest residual, named:** a provider that reads all bytes and then fabricates output is out of scope — the provider is the trusted compute, and if it lies the review content is worthless regardless of delivery attestation. The mechanism converts "read nothing, exit 0" from *undetectable* to *impossible without active forgery*. The attestation semantics of `dispatchPromptSha256` become: complete byte stream presented, fully accepted by the OS, and (explicit mode) terminally echoed — not "semantically attended to."

**Acceptance fixture matrix — replaces the inadequate single 80 KiB fixture.** Mandate a **4 KiB** payload for the sub-buffer regime (below every common platform default; Linux's default is 64 KiB). Required cells:

1. 4 KiB, child reads nothing, exits 0, no echo → `KSTACK_CONSUMPTION_UNCONFIRMED`, no manifest/envelope. This is the exact case the round-4 design passes silently; this cell demonstrates the closure.
2. 4 KiB, child reads all, echoes a wrong nonce → fail closed.
3. 4 KiB, child reads all, correct echo, exit 0 → accepted.
4. Correct echo but nonzero exit → fail closed.
5. Keep the ≥80 KiB prefix-read/EPIPE/premature-close fixtures for the backpressure regime.
6. Keep the one-good-sibling-cannot-publish dual-review case.

## Ruling 2 — variant-registry tamper-evidence (variant-registry-not-tamper-evident, and SEC-VARIANT-RACE folded in)

**Implement a lightweight append-only hash chain; signatures and external attestation are rejected as disproportionate.** Each attempt record carries `{seq, prevRecordSha256}` — seq contiguous from 1 per design, first record's prev the zero digest. Gate-time verification requires chain continuity; `variantSetSha256` is computed over the verified chained set; and the gate decision additionally binds `registryHeadSha256`, the digest of the last record.

**The same mechanism closes Codex's SEC-VARIANT-RACE:** every consumer of a gate decision recomputes the live registry head and fails closed on mismatch. A later-registered attempt advances the head and automatically stales the decision — revalidation rather than freezing, with no lock-lifetime problems. One mechanism, two HIGH findings, closed in one pass.

**Proportionality, consistent with the citation-grounding round-14 reasoning:** the threat model is a trusted local account with repo write access — an actor who can rewrite the enforcing gate code itself. Signatures stored in the same repo would only simulate assurance against that actor. The chain is real protection against the realistic cases (accidental deletion, partial syncs, cleanup scripts, casual tampering, post-decision registration), and its limit must be disclosed plainly: a same-user actor who rewrites the entire chain pre-decision is an accepted residual, consistent with the design's existing same-user-modification residual. Also state plainly, per Opus's request, that root enumeration is config-trusting. An external transparency anchor may be named as a future upgrade path but is not required for v1.

## Ruling 3 — raw unsanitized stdout retention (raw-report-secret-retention)

**Decouple hashing from retention; retention is demoted from approval precondition to a governed, default-off option.**

- **Unchanged and mandatory:** hash raw stdout first (`rawReportSha256`), then sanitize a copy and hash the stored sanitized bytes (`reportSha256`); the manifest records both digests, both byte counts, and sanitizer ID/version. **Digest recording — not retention — is the approval precondition.**
- **New config `retainRawReports`, default `false`.** When false, raw bytes are hashed **in memory and never touch disk** — write-then-delete leaves residue and reopens the exposure being closed. The manifest records `rawReportRetained: false`; the disclosed residual is that raw bytes cannot later be re-inspected, though the digest still attests them.
- **When true, all of these controls are mandatory:** storage under a configured raw-report root whose gitignore coverage is verified by CI; mode 0600; the root must lie outside any backup/sync path; a retention window (default 90 days after the envelope decision, config-overridable) with erasure performed by release tooling; the manifest records path and erasure-due date. **No encryption-at-rest mandate** — under the same-user threat model the keys would be co-resident with the data; it is theater.
- Approval **never** fails closed for choosing non-retention; the round-4 sentence mandating retention as a precondition is struck. The rationale is Opus's own weighting: the new exposure was "larger and less governed than the ambiguity it removes." Forcing durable secret-bearing artifacts to exist, in a project whose sanitizer exists because provider output has carried credentials, inverts the security priority.

## Scope

This ruling covers exactly the three arbitrated items plus the SEC-VARIANT-RACE fold-in. SEC-MIGRATION-PROVENANCE and all remaining round-4 findings — CRLF cost breach, malformed-UTF-8 fail-closed, evaluation power and staffing, Unicode version-bump procedure, the stale compliance sentence, checked-in per-body digests — proceed through normal round-5 revision; my silence on them is not an override. Nothing in them conflicts with these rulings; the malformed-UTF-8 fail-closed fix in particular is consistent with Ruling 1's attestation semantics and should be adopted as Opus specified.
