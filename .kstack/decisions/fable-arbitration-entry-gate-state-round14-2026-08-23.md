# Fable arbitration ruling — citation-grounding design loop, entry-gate state-machine fork (round 14)

**Date:** 2026-08-23
**Arbiter:** Fable (claude-fable-5), invoked on genuine structural non-convergence: five consecutive rounds (10–13 plus round 13's review) of real findings in the same entry-gate state/locking subsystem, each fix sound in isolation and defective in composition — the same signature I resolved twice this session in the Reflexion design.
**Question ruled on:** Continue patching the hash-chain/epoch/CAS entry-gate state machine (A), replace it with the simpler pattern already proven in this repository (B), or a narrower compaction fix (C).
**Scope continuity:** My round-5 ruling stands unchanged and is not reopened. This ruling governs only the entry-gate state/locking subsystem.

## Ruling: Option B

Replace the hash-chain/epoch/CAS entry-gate state mechanism with a single state file using the plain-read / bounded-relock / atomic-replace pattern this repository already uses successfully for the Reflexion lesson corpus. Round 14 is a **replacement round**: it implements the mechanism specified below verbatim, deletes the machinery listed below, and fixes the enumerated carried-forward findings that Option B does not moot.

## Basis

**1. The precision being purchased is worthless under the design's own threat model.** The round-13 draft states, in its own words, that the state is "evidence used by a locally run workflow, **not** a security control against an adversary able to write as that account," and that such an actor "can forge pass/go despite hashes, permissions, a local instance binding, or reason codes." The hash chain's tamper-evidence therefore protects against nobody: the trusted single operator does not need it, and the only adversary who could tamper defeats it by the draft's own admission. What remains as a genuine requirement is crash consistency — and the accepted remediation for *every* ambiguous-state case is already "effective off, rerun smoke+shadow," a smoke test plus 5–10 dual runs. The chain exists to precisely distinguish crash cases whose distinction changes nothing the operator does. This is the round-5 proportionality reasoning applied one layer down: a subsystem whose cost cannot converge against the value it delivers.

**2. The empirical record points at the simple mechanism, not the chain.** The single best-attested primitive on this mount is atomic closed-file rename-over: 2,000 concurrent complete-temp rename-overs against 3,859 reads with zero ENOENT and zero torn bytes — the strongest positive evidence in the entire five-round record. The chain's declared linearization point — concurrent hard-link publication — is the one primitive **never** concurrently tested, and its failure mode is total: `HARDLINK_CAS_BROKEN` blocks the whole feature with no fallback publication mechanism designed. Opus itself flagged this evidence misallocation in round 12 (the design "demoted" the stress-tested primitives and promoted the once-sequentially-tried one). Option B corrects the misallocation by building on the primitive the evidence supports.

**3. The design already trusts rename-over at its most critical point.** The active-chain descriptor — the root of *all* authority, which selects the epoch every reader and writer trusts — is published by unconditional rename-over. The CAS discipline is enforced only where it matters less. If rename-over is acceptable for the root, it is acceptable for the two booleans and one counter the root exists to protect.

**4. Five rounds of structural non-convergence is the decision criterion my prior arbitrations established.** Rounds 10 through 13 each resolved the immediately-prior finding while generating a new one in the same subsystem. Round 13's review yields five more real defects (unbounded traversal, rename-over-vs-CAS inconsistency, orphan-marker authority, non-terminating interrupted-rotation repair, unverified linearization primitive). The mechanism is generating obligations faster than rounds discharge them.

**Rejection of (A):** the round-14 patch list — compaction/checkpointing, descriptor CAS, marker-removal authority protocol, rotation-resume protocol, concurrent-probe fallback design — is machinery of exactly the class that produced the previous five findings. The predictable outcome is that round 15 finds the composition defect in the checkpoint mechanism.

**Rejection of (C):** a tip-in-descriptor checkpoint fixes one of the five open findings, reintroduces rename-over into the hot authority path (the very inconsistency Opus flagged), and creates a *second* authority root whose composition with slots, markers, and rotation must itself be specified and reviewed. That is the defect-generating pattern, not an escape from it.

**Disposal of the reviewers' prior "no redesign warranted" statements.** Opus round 13 wrote "the scope and architecture are sound and no redesign is warranted," and Opus round 12 pre-emptively dissented from redesign verdicts on the CAS chain. Those verdicts assessed the mechanism's *internal* soundness, which this ruling does not dispute — the hard-link CAS chain is a genuine resource-level fence. The arbitration question is proportionality and convergence across rounds, which reviewers inside the loop were not asked and structurally cannot judge one round at a time. Those prior statements are **superseded for round 14**: reviewers must not cite them against the replacement.

## The replacement mechanism (binding specification for round 14)

**Data.** One file, `.kstack/state/citation-grounding-v1.json`, canonical JSON ≤ 16 KiB, mode 0600, in `.kstack/state/` (0700). Closed schema retaining exactly the round-13 draft's state *content* minus all chain fields: `stateSchemaVersion`, `deploymentFingerprint`, platform-receipt binding, `localGateInstanceId` binding, the smoke record (result, `smokeAttemptsSinceFingerprint`, timestamps, fixture/result hashes, attempt number), the shadow record (judgment, `dualRuns`, closed reason codes, timestamp), `advisoryRunsSinceGo`, plus two new fields: `stateGeneration` (monotonic integer, diagnostic only — not a CAS key) and `mutationInProgress` (null, or `{kind, mutationId, startedAt}` — this replaces the revocation-marker file). **Deleted:** `chainEpochId`, `priorStateGeneration`, `priorStateSha256`, the `.chains/` epoch directories, commit slots, active-chain descriptor, revocation-marker file, archive, and the performance cache.

**Reads** (every gate check): open by path, read whole file, strict parse/validate. ENOENT → `STATE_NOT_QUALIFIED`. Parse/validate failure → exactly one immediate bounded re-read (tolerates catching an in-flight rename); second failure → `STATE_MALFORMED`, effective off. `mutationInProgress` non-null → non-enabling: `STATE_NOT_QUALIFIED` with closed detail token `MUTATION_IN_PROGRESS`; remediation is simply rerunning the smoke/shadow entry sequence, which lawfully overwrites the in-progress record — **no locked-repair command, no marker-removal authority question exists**. Fingerprint, TTL, and run-limit checks are unchanged from round 13.

**Writes** (all mutations — smoke result, shadow result, ordinary-run reservation, in-progress record): acquire the existing coordinator lock (the round-13 `wx`-create lock with its existing timing constants survives **unchanged** — it is mount-verified, and its best-effort character is now sufficient because the consequence of the rare stale-holder race is bounded and advisory-only); re-read and validate state under the lock; construct the complete successor with `stateGeneration + 1`; write to a same-directory `wx` 0600 temp file; fsync; close; rename over the state path; fsync the directory; fresh-open read-back byte comparison; release the lock. This is the Reflexion lesson-corpus write pattern, cited as in-repo precedent.

**Pass/go-replacing operations** keep revocation-first in its trivial form: under the lock, atomic-replace the state with `mutationInProgress` set (non-enabling); release the lock; do the provider/operator work; reacquire the lock; re-read; verify the same `mutationId`; atomic-replace with the final result and `mutationInProgress: null`. A crash at any point leaves either the old state (work never recorded — rerun) or a non-enabling in-progress state (rerun overwrites). Both remediations are the same command the operator was already running.

**Ordinary run reservation:** under the lock, read; require enabling state, `advisoryRunsSinceGo < 50`, and valid TTL; write the successor with the counter incremented; release; dispatch only after confirmed read-back. Crash before rename consumes nothing; after, one allowance. Identical semantics to round 13, minus the chain.

**Reason tokens** collapse to a closed set of **six**, precedence in this order: `LOCK_CONTENTION`, `PLATFORM_PRECONDITION_FAILED`, `STATE_MALFORMED`, `STATE_EXPIRED`, `STATE_RUN_LIMIT_REACHED`, `STATE_NOT_QUALIFIED`. `STATE_REVOKED` and `STATE_EXHAUSTED` are deleted; every path that produced them now maps to `STATE_NOT_QUALIFIED` with a closed detail token or disappears with the machinery that produced it.

**Accepted residual (must appear in the draft as accepted, not defended as impossible).** A stale process paused past the 90-second stale threshold whose lock is broken, resuming precisely between its final ownership check and its rename, can clobber a newer state (a lost update). Relatedly, an ordinary reservation that passes read-back may dispatch while a smoke rerun's in-progress write lands just afterward. Consequences are bounded and advisory-only: worst case is either up to 50 extra advisory runs under a resurrected enabling record — which blocks nothing and sends v2 prompts to the same providers the legacy path already talks to — or one redundant re-qualification. Resurrection is bounded in time because **the TTL check reads the resurrected record's own timestamps**: a clobbering old record carries its original smoke/shadow timestamps and expires on its own 14-day clock, and the fingerprint binding rejects it across any deployment change. Under the single-operator trusted-account threat model this residual is accepted. This closes the round-12 stale-holder finding by acceptance-with-bounded-consequence rather than by mechanism: that finding demanded resource-level fencing while the design still aspired to overwrite-proof state; the replacement explicitly does not so aspire, per the threat model the design itself declared.

**Platform contract shrinks** to clauses (a) O_EXCL, (b) directory fsync accepted (same durability disclosure), (c) stable dev/ino across opens and rename (needed for lock snapshots), (d) atomic closed-file rename-over — already concurrently stress-tested, (e) pathname utimes (lock heartbeat), and (g) inherited-fd read after unlink. Clause (f) and `HARDLINK_CAS_BROKEN` are deleted. Every retained clause now has direct positive evidence from rounds 12–13, which closes the "asserted, not demonstrated" / permanent-inertness family entirely.

**Deleted outright with the chain** (removed, not deferred-in-place): epochs, `--rotate-citation-grounding-chain`, the archive, hard-link CAS publication, revocation-marker mutationId rules, `STATE_EXHAUSTED`, `MAX_STATE_TRANSITIONS` and its cap fixtures, the performance cache, interrupted-rotation repair, and all chain-traversal reader rules.

## Carried-forward round-13 findings that Option B does not moot

Round 14 must also fix these; all are cheap specification fixes plus one fixture:

1. **Pin the staging directory** normatively to the receipted state filesystem (same device), and extend the checked-in integration test to the composed real ordering: positional verification reads → fstat → spawn → confirm creation → activate → unlink → child reads all bytes from zero. Add the implementation-time check that at least one real configured provider CLI tolerates unlinked stdin, or defer unlink until child close for unverified adapters. (Opus r13 #2/#3/#4; Codex r13.)
2. **Version-probe/fingerprint acquisition failure** maps to `PLATFORM_PRECONDITION_FAILED` with new closed detail token `VERSION_PROBE_FAILED`; remediation text names executable/configuration repair. This is ruled, not drafter's choice. (Codex r13 #2; Opus r12 #3.)
3. **Git-check-impossible conditions** get their own closed detail token and remedy text distinct from "rerun smoke/shadow." (Opus r13 #8.)
4. **Smoke predicates:** drop the entailed combined 98/100 floor or restate it as derived, so the predicates are honestly presented. (Opus r13 #10.)
5. **Invalid `citationGrounding` config value:** state the runtime consequence explicitly. (Opus r12 #8.)

Mooted by B: unbounded traversal, rename-over-vs-CAS descriptor inconsistency, orphan-marker authority, interrupted-rotation repair, precondition (f), genesis-representation ambiguity (Codex r13 #3 — no genesis exists), and SEC-REVOCATION-ORDER in its chain form (its analogue is covered by the accepted-residual paragraph above — the in-progress record lives inside the single state file read under the same lock, and the narrow remaining window is disclosed there, not denied).

## Process directives for round 14

- **Round 14 is a replacement round**, analogous to round 6's subtraction round: the drafter implements this ruling's mechanism verbatim, deletes the listed machinery, and fixes carried-forward items 1–5. Reviewers review against **this ruling's mandate**: they must not demand chain-grade overwrite-proofing from a mechanism this ruling has declared advisory-and-accepted. The accepted-residual paragraph is reviewable for wording and completeness of disclosure, not for whether the residual should exist.
- **Reasoning effort: High** for the round-14 drafting dispatch and both reviews. This is a subtraction-plus-known-pattern round; nothing in it matches the Highest-tier categories. No xhigh anywhere in round 14, including this arbitration's implementation.
- **No new empirical probes are required at design time**: every retained platform clause already has direct evidence. The composed staging fixture and real-CLI stdin check are implementation-time obligations, as before.
- The loop continues per standing policy — design loops never auto-stop. One calibration signal, judged on substance and not round count: if round 14's review produces a "revise" against the *replacement state mechanism itself* (as opposed to the carried-forward items), that falsifies this ruling's proportionality premise and warrants surfacing to the operator before round 15 — not another arbitration by default.
