# Fable arbitration ruling — citation-grounding design loop, write-gating vs. requalification recovery (round 17)

**Date:** 2026-08-23
**Arbiter:** Fable (claude-fable-5), third invocation on this design, second on the entry-gate subsystem. Invoked on a genuine specification conflict inside the round-14 replacement mechanism: the design's write-gating rules, read literally, forbid the very write its own recovery remedies prescribe.
**Scope continuity:** The round-5 scope ruling and the round-14 replacement ruling stand unchanged and are not reopened. This ruling governs only the write-gating/requalification tension inside the round-14 single-file mechanism, plus the disposition of round 16's secondary findings.
**A note on the character of this arbitration:** this is not an adversarial fork. Codex's recommendation *is* an operation-specific transition matrix; Opus's *is* a correction of the counter's semantics and disclosure. The two reviewers converge; what was missing was a binding decision on the principle and its exact edges. This ruling ratifies their convergent recommendations and makes them normative.

## Ruling on question 1: genuine conflict, resolved by classification — not a new mechanism

Codex is right that the conflict is real as written: the closed write-path table's "Do not write" rows for `STATE_EXPIRED`, `STATE_RUN_LIMIT_REACHED`, `FINGERPRINT_MISMATCH`, and `PLATFORM_RECEIPT_MISMATCH` apply to "all mutations," which includes the smoke start those rows' own remedies prescribe. The exhaustion remedy is likewise non-executable: after a `qualificationBudgetEpoch` replacement, the old record mismatches the new fingerprint and no specified transition lets smoke replace it. Every recovery path terminates in a command the table orders to refuse.

The resolution is a narrow, principled classification, binding for round 17 — the **entry-replacement principle**:

> The state file is the record of the **current qualification cycle**. Entry commands create and replace that record wholesale; dependent commands only read it and reserve against it. Therefore the validity of the *existing* record's qualification — expired, run-limited, fingerprint-mismatched, receipt-mismatched, qualification-absent, mutation-in-progress — gates only **dependent writes**, never **replacement writes**, because for a replacement write those conditions are precisely what is being repaired.

Concretely, writes divide into exactly two categories:

- **Replacement writes:** smoke start and finalization, shadow start and finalization, and the existing lock-guarded malformed-state reset. A smoke start is permitted, under the lock, to replace state that is absent, expired, run-limited, fingerprint-mismatched, receipt-mismatched, qualification-absent, or mutation-in-progress (the existing overwrite rule). A shadow start requires a current-fingerprint, unexpired, confirmed smoke pass, and may replace any prior shadow judgment or in-progress record.
- **Dependent writes:** the ordinary-run reservation. It requires fully enabling state, exactly as round 16 specifies. Unchanged.

Replacement writes remain gated by exactly three things, and nothing else:

1. **Environment health** — platform preconditions, coordinator lock, Git check (`GIT_CHECK_IMPOSSIBLE` stays universal; it is about the environment, not the record).
2. **Strict malformedness** — two complete malformed reads is still `STATE_MALFORMED` for every command; only the deliberate reset command may act on it. Deletion authority stays where round 15 put it.
3. **One policy gate — the unified exhaustion predicate**, which replaces Opus's three inconsistent phrasings with a single normative form: a smoke start refuses with `STATE_NOT_QUALIFIED` + `SMOKE_ATTEMPTS_EXHAUSTED` if and only if **the stored fingerprint equals the current recomputed fingerprint, AND the attempt counter is 3, AND the stored smoke result is not `pass`**. When any leg fails, the start proceeds.

**Successor-count rule (binding, closes the count-4 corner):** a smoke start's successor sets the counter to **1 when it begins a fresh cycle** (the stored record carries a confirmed pass, or the stored fingerprint differs from the current one) and to **observed + 1 otherwise** (bounded ≤ 3 by the exhaustion gate above). The clobber-reachable "count 3 with a current pass" state is therefore lawful input beginning a fresh cycle — no successor can ever carry count 4, and step-4 self-validation failure becomes unreachable from any specified state. A residual step-4 self-validation failure is by definition an implementation invariant violation, not a state or platform condition: the command aborts nonzero with a payload-content-free internal-error diagnostic, writes nothing, and emits no reason token — it is outside the six-token surface, and the table gets a row saying exactly that.

**The six-token reason surface is unchanged.** No token or detail is added or removed by this ruling; only the mapping of which command categories the existing rows govern changes. Reviewers must not read round 17 as reopening the round-14 closed surface.

**Sticky exhaustion is a ruled policy choice, not an oversight:** a count-3-no-pass record at a stable fingerprint remains exhausted **across TTL expiry and across the run-limit** — only the reviewed epoch change reopens attempts. Rationale: the budget gates broken-deployment retries; what TTL expires is a pass, and there is no pass. The passage of 14 days does not repair a deployment that failed three consecutive smoke starts. This must be stated in the draft as a decided property, with a fixture (count-3-no-pass, advance past TTL, prove smoke still refuses with the epoch remedy).

**Remedy-executability rule (binding acceptance criterion, the class-level guard):** for every non-enabling reason token and detail pair, the acceptance suite must include a fixture that starts from a state emitting that token and executes the token's stated remedy sequence **to completion** — proving every prescribed command actually runs from the state that prescribes it. The remedy text for `STATE_EXPIRED`/`STATE_RUN_LIMIT_REACHED` also gains one sentence: if the prescribed smoke rerun refuses with `SMOKE_ATTEMPTS_EXHAUSTED`, follow that remedy (the one extra diagnostic hop in the co-present expiry-plus-exhaustion case is accepted as deliberate, answering Opus's unresolved question 7). This rule is what makes this the last arbitration on prescribe-a-refusing-command defects: it converts the whole class from review-detectable to fixture-detectable.

## Ruling on question 2: no second aggregate bound; the counter's semantics are corrected, not just disclosed

The reset-on-pass fix stands. **No resets-per-TTL-window cap or any other second budget is added.** A capped-resets counter is precisely the composed-state machinery class my round-14 ruling removed — its own field, its own reset rule, its own exhaustion token and remedy, its own clobber interaction, its own fixtures — erected to bound a provider-cost exposure that only the trusted single operator or their own buggy script can incur, in an advisory-only feature that blocks nothing. On the ordinary path, requalification frequency is governed by TTL, the 50-run limit, and deliberate operator invocation, all trusted under the declared threat model. Opus's own severity call (low) is correct.

But Opus's material dissent is also correct and is adopted in full: **option (a) changed what the counter means, and the draft must say so as correction, not disclosure.** The counter's guarantee, restated normatively:

> The counter bounds **consecutive non-passing smoke starts within one qualification cycle** at three, forcing diagnosis and a reviewed epoch change before a fourth consecutive non-passing start. It does not bound, and was not retained to bound, aggregate lifetime smoke invocations for a working deployment.

Binding corrections for round 17:

1. **Rename the field** from `smokeAttemptsSinceFingerprint` to **`smokeStartsThisCycle`**, with a normative definition of *cycle*: a cycle begins at a fingerprint change or at a confirmed pass, and ends at a confirmed pass. Rename it **everywhere** — schema bullet, reads section, every table row, the smoke-test section, Tradeoffs, and every fixture description. A half-renamed draft is a fourth inconsistency, not a fix.
2. **Correct the "no runtime flag or reset command can reopen attempts" sentence** to its true scope: no runtime path reopens attempts after three consecutive non-passing starts at a stable fingerprint; a confirmed pass ends its cycle and is not a reopening.
3. **Rewrite the Tradeoffs attribution.** More-than-three aggregate provider-calling smoke starts per fingerprint has two distinct sources, both named: (i) the ordinary repeated-pass path — deliberate, each cycle individually bounded at three, aggregate cycles unbounded by design because each pass evidences a working deployment; and (ii) the accepted stale-clobber residual — unchanged from round 16. The current clobber-only attribution is deleted.
4. **Ordinal independence:** the passing/failing attempt ordinal (1–3) records which start of its own cycle terminated the cycle and is normatively independent of the counter; ordinal 3 alongside count 0 is a legal, expected post-pass record. Explicit schema statement plus a fixture asserting a post-reset pass record validates.
5. **Repeated-pass fixture:** a fixture pinning repeated passing smoke cycles on a stable fingerprint as decided behavior (each cycle consumes and resets; aggregate starts exceed three; no refusal), so the property is a tested decision rather than an emergent one.

## Ruling on question 3: no replacement mechanism; the principle is the class fix

The entry-replacement principle in ruling 1 is not a patch of the same species as rounds 10–13 — it is a re-derivation of what the round-14 single file *means* (the record of the current cycle, wholly replaced at each entry), applied consistently to the failure table that was written before that meaning was articulated. It adds no field, no file, no token, no protocol. Every genuinely simpler-looking alternative — splitting qualification and reservation into separate files, or an append-only budget ledger — reintroduces exactly the multi-artifact composition the round-14 ruling removed, and is rejected. The remedy-executability fixture rule is the structural guard that prevents this conflict class from recurring in any future row. If round 17's review finds a defect in the *principle itself* (not its wording), that falsifies this ruling's premise and warrants surfacing to the operator — not a fourth arbitration by default.

## Disposition of round 16's secondary findings

These accompany the ruling so round 17 closes in one pass. **Binding** (they touch the ruled mechanism): the unified exhaustion predicate, the successor-count rule, the count-4 closure, sticky-exhaustion disclosure and fixture, the remedy-executability fixtures, and all five numbered corrections in ruling 2. **Directional, with drafter latitude on wording** — the drafter follows the stated direction; reviewers may refine wording without treating these as arbitration-locked:

1. **Malformed/invalid coordinator-lock record** (both reviewers): within the lock budget, a present-but-unparseable lock record is indistinguishable from a live owner and maps to `LOCK_CONTENTION` (retry is the correct remedy either way). At or past the 90-second age by file mtime, it is stale-breakable through the existing tombstone path, with the two required snapshots compared on raw bytes plus `(dev, ino)` rather than parsed fields. Lock-lifecycle I/O stays `PROBE_IO_ERROR`. No new token.
2. **Read-back absence vs. concurrent unlink** (Opus): the platform probe is the sole authority for `RENAME_REPLACE_BROKEN`. A single operational absent-path-after-reported-rename maps to `PROBE_IO_ERROR` with the retry-and-rerun-platform-check remedy; the rerun probe then either reproduces the violation (capability verdict) or passes (transient/concurrent explanation, retry). This removes the misleading move-filesystems remedy from the ambiguous case.
3. **Staging create/write/verify failures** (Opus): pre-spawn staging failures are preparation-time local failures explicitly inside the "local spawn failure before activation" symmetric `legacy_fallback` rule; staging `EEXIST` gets the same three-attempt fresh-random-name rule as the state temp file, with exhaustion also taking fallback. They get no rows in the state failure table — staging is the dispatch path, not the state write path.
4. **Catch-all errno remedy** (Opus): broaden `PROBE_IO_ERROR` remedy wording to be environment-neutral (local I/O or runtime fault; rerun the platform check, which distinguishes storage-health problems; a persistently failing operation under a repeatedly passing platform check is treated as an implementation defect to report, not a storage problem).
5. **25-hour staging-retention claim** (Opus): restate as conditional — the bound holds absent PID reuse and with liveness checks available; both exceptions already in the text become qualifications of the stated maximum rather than contradictions of it.
6. **`CREDNAME-PATTERN-INCOMPLETE`** (Opus, medium): extend the deny pattern to at least `PAT`, `BEARER`, `PASSPHRASE`, `SIGNING`, `SALT`, and `ACCESS[_-]?KEY`, and state plainly that the conformance rule catches only matches — non-match coverage remains a reviewed maintainer obligation, as the manifest-completeness limitation already is.
